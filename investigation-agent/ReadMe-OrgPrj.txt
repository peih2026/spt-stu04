作成日: 2026-06-03

1. プロジェクト概要

本プロジェクトは「株式会社サンプル商事」システム部が管理する 2 つの社内システムで構成される。

  プロジェクト名  : poc-investigation-targets
  OMS 運用開始    : 2008 年
  ETL 運用開始    : 2017 年
  管理部門        : システム部（兼任担当: 鈴木）
  利用者          : 社内営業担当・在庫管理担当（社内 LAN 限定）

  サブシステム一覧
  ┌──────────────────────────────────┬──────┬────────────────────────────┐
  │ サブシステム                      │ 略称 │ 目的                       │
  ├──────────────────────────────────┼──────┼────────────────────────────┤
  │ legacy-order-inventory-system    │ OMS  │ 受発注・在庫管理（業務中核） │
  │ asteria-etl-sample               │ ETL  │ OMS と DWH 間のデータ連携   │
  └──────────────────────────────────┴──────┴────────────────────────────┘

3.5 主要業務フロー

  ■ ログイン処理
    1. login.jsp で ID / パスワードを入力して POST
    2. LoginServlet が M_USER テーブルをクエリ（MD5 ハッシュ照合）
    3. 認証成功 → HttpSession に USER_ID / USER_NM / DEPT_CD を格納し menu.jsp へ遷移
    4. 認証失敗 → login.jsp にエラーメッセージを返却

  ■ 受注登録フロー
    1. order_new.jsp で取引先・商品・数量を入力して POST
    2. OrderServlet が T_ORDER（ヘッダ）と T_ORDER_DTL（明細）に INSERT（STATUS_CD='00'）
    3. 確定操作 → STATUS_CD を '10' に UPDATE し InventoryDAO.decreaseStock() で在庫引き当て
    4. InventoryTrx に OUT レコードを登録

  ■ 受注取消フロー
    1. OrderServlet.doCancel() が T_ORDER の STATUS_CD を '90' に UPDATE
    2. 引き当て済み在庫を InventoryDAO で戻す（InventoryTrx に IN レコード登録）

  ■ 在庫照会・調整フロー
    1. InventoryServlet.doGet() が warehouseCd パラメータを受取り inventory.jsp を表示
    2. 調整入力後に POST → InventoryDAO.decreaseStock() を呼び出し
    3. InventoryTrx に OUT / ADJ レコードを登録

4.2 フロー構成
  ┌──────────┬────────────────────────────┬───────────────────────────────────┬────────────┬──────────┐
  │ フローID │ フロー名                   │ 目的                              │ スケジュール│ 状態    │
  ├──────────┼────────────────────────────┼───────────────────────────────────┼────────────┼──────────┤
  │ FLW-001  │ customer_master_sync       │ 取引先マスタを OMS→DWH へ同期    │ 平日 06:00 │ 稼働中   │
  │ FLW-002  │ order_etl_daily            │ 受注データを OMS→DWH へ日次連携  │ 毎日 02:30 │ 稼働中   │
  │ FLW-003  │ inventory_reconcile        │ 在庫数突合・差分レポート出力      │ 月初 04:00 │ 稼働中   │
  │ FLW-099  │ legacy_csv_export          │ 旧 BI 向け CSV 出力（無効化済）   │ 手動       │ 無効     │
  └──────────┴────────────────────────────┴───────────────────────────────────┴────────────┴──────────┘

  FLW-001: customer_master_sync コンポーネント
    C1 DBInput    : M_CUSTOMER 全件 SELECT
    C2 Mapper     : 列名変換・DEL_FLG='1' レコードをフィルタ除外
    C3 DBOutput   : DIM_CUSTOMER を truncate_insert（全件洗い替え）
    C4 ScriptTask : 処理件数カウント
    C5 MailSend   : it-ops@example.co.jp へ SMTP 通知

  FLW-002: order_etl_daily コンポーネント
    O1 DBInput    : T_ORDER を全件 SELECT（ORDER BY ORDER_DT）
    O2 LookupDB   : M_CUSTOMER から CUSTOMER_NM を件ごとに取得
    O3 XSLT       : order_transform.xsl で DWH 形式へ変換・税率計算
    O4 FileOutput : order_YYYYMMDDHHMM.tsv をファイル共有へ出力
    O5 DBExecute  : FACT_ORDER を TRUNCATE → BULK INSERT
    O6 MailSend   : it-ops へ SMTP 通知

  FLW-003: inventory_reconcile コンポーネント
    I1 DBInput（OMS）: T_INVENTORY を倉庫別に取得（W001 / W002 / W003）
    I2 DBInput（DWH）: DIM_INVENTORY から在庫取得
    I3 Merger        : 商品コードキーで OMS と DWH の在庫数を突合
    I4 Filter        : 数量不一致のレコードのみ通過
    I5 FileOutput    : 差分レポートを CSV 形式でファイル共有へ出力
    I6 MailSend      : 突合結果サマリを SMTP 送信

4.4 XSLT 変換ロジック（order_transform.xsl）
  ┌──────────────────────┬─────────────────────────────────────────────────────┐
  │ 処理                 │ 変換内容                                            │
  ├──────────────────────┼─────────────────────────────────────────────────────┤
  │ フィールドコピー     │ ORDER_NO/ORDER_DT/CUSTOMER_CD/STATUS_CD/TOTAL_AMT   │
  │                      │ を無変換で転送                                      │
  │ 取引先名付与         │ LookupDB で取得した CUSTOMER_NM をセット            │
  │ 税率判定             │ REMARKS に「軽減」→0.08 /「非課税」→0.00 / 他→0.10 │

  │ 販売チャネル         │ 固定値 "STORE" をセット                             │
  │ 通貨                 │ 固定値 "JPY" をセット                               │
  │ 取込日時             │ LOAD_AT に ETL 実行時のシステム日時をセット         │
  └──────────────────────┴─────────────────────────────────────────────────────┘
